GlowySilver Epyrus - porting notes
======================================


1.0.0rc1
--------
- First release candidate under the final name GlowySilver Epyrus.
- Based on the cleaned 0.1a28 development baseline; no intentional visual changes.
- Release metadata and licensing/attribution files added.
- Original GlowySilver Thunder theme by glowplug is GPL v3.0.
- Selected artwork derived from the Epyrus default theme remains MPL 2.0.

0.1a7
-----
Secondary UI transplant / dark-surface audit.

- Parked the experimental Compose dark-canvas XBL hook from 0.1a6. The Compose
  chrome remains dark, but the message body canvas is intentionally left at
  Epyrus default until that issue is revisited.
- Added Epyrus 2.2.1/TB52-generation coverage for Preferences and application
  handler lists, while preserving the original Glowy preference artwork.
- Added current Address Book surfaces and selection states (directory tree,
  results tree, card view and headers).
- Added current Account Manager tree/archive/identity/SMTP dark surfaces.
- Hardened the current Add-ons Manager list/detail/category/search surfaces.
- Removed explicit light EULA, tab-modal prompt, about and support field
  backgrounds that could break the full-dark design.
- Kept Linux and Windows corrections separate; both disable native light
  painting on the newly audited secondary tree/list surfaces.

Open issue: Compose message-body editing canvas is still white. No further
experimental runtime hook is active in this build.

0.1a4
-----
Compose transplant based on the current Epyrus 2.2.1 / TB52-generation
compose structure. Added dark styling for the compose toolbox, headers,
recipient addressing widget, Subject, attachment pane, Format toolbar,
notifications, findbar and editor frame.

The editable message document is darkened through a chrome.manifest redirect
of chrome://editor/content/EditorContent.css. Epyrus editor.js loads that URI
as an nsIEditor override stylesheet. This is intentionally display-only: the
dark background and light foreground are not inserted into the message DOM and
therefore are not serialized into outgoing HTML or plain-text mail.

Linux/Windows platform layers remain separate. No intentional changes were
made to the already-tested 0.1a3 Messenger menubar geometry fix.

0.1a3
-----
Hotfix: keep menubar item geometry constant between normal and hover/active
states. The old Thunderbird 11 rule added top padding and changed border widths,
which made Epyrus resize the menubar and shift the entire content area down.
No other visual area was intentionally changed in this build.

This build starts the actual Messenger transplant.  It does not simply bump
compatibility metadata: the current Epyrus/TB52-generation selectors are now appended to the
corresponding Messenger stylesheets (mailWindow1, tabmail, quickFilterBar,
messageHeader and messenger) while retaining the original Glowy textures,
colours and artwork.  epyrus-messenger.css is retained as an audit/mapping file.

Audited / adapted in 0.1a2:
- main 3-pane surfaces (mailContent, folder/thread trees, message pane)
- current grouped-thread and selection selectors
- folder pane header and toolbar
- current navigation toolbox and tab strip internals
- current Quick Filter Bar selectors
- current message header / attachment / notification surfaces
- search and status surfaces
- Linux and Windows compatibility layers kept separate from shared styling

Still donor-first / pending deeper Epyrus transplant:
- full toolbar icon selector audit
- Compose editor and all addressing/format controls
- Address Book
- Preferences / Account Manager
- Add-ons Manager
- dialogs and secondary windows
- Calendar/Lightning integration

The old donor CSS remains intentionally present for visual coverage while each
area is migrated to current Epyrus selectors.  This makes regressions easier to
localise during alpha testing.
